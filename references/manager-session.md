# 经理初始化与接管

仅在用户明确指定/接管经理，或已有经理的真实管理请求需要路由自修复时阅读。只问状态走入口的只读采集路径，不执行本文步骤。标准后端为仓库根 `TASKS.csv`；已存在的其他任务体系先核项目契约、复用后端，不直接创建第二套真源。用户明确要求接管当前目录时，缺少管理结构就创建；不能因没有账本或目录是管理工作区而自行判定“不适用”。明确接管授权覆盖必要控制面创建，不覆盖新业务交付。

## 正常初始化

以约10秒、正常不超过30秒为交互目标，不保证外部工具延迟。复用已提供的仓库指令与真实身份，不为初始化读取历史成果、产品实现、远程会话目录或安装 Hook。

1. 批量核对缺少的仓库指令、项目名称和当前真实会话身份。按当次宿主工具声明发现命名能力，将当前经理会话命名为 `项目经理：<项目名称>`，再用宿主读取/列表能力回读同一真实 ID 的标题。已有标题符合时只核对；项目名称缺失时在第2步确认配置后补做。身份不能猜：由宿主、用户或初始化脚本显式提供可验证的真实会话 ID（如 `initialize-manager.mjs --manager-thread <真实ID>`）。不为命名创建另一个经理、替换登记身份或重启服务。无命名能力、调用失败或无法回读时明确报告具体缺口并保留命名/核对待办，继续可做的控制面工作，不静默取消要求。
2. 运行一次 `node <Skill>/scripts/initialize-manager.mjs --repo <仓库> --manager-thread <真实ID>`。缺少 `TASKS.csv` 时自动调用 `init-project.mjs --empty` 创建空账本、配置、详情目录和生成看板，保留原 `AGENTS.md` 并追加任务系统入口；不创建示例任务。可传 `--prefix`/`--name`，缺省采用稳定的目录路径哈希前缀和目录名（它们不是会话身份）；配置已存在时保留其设置。创建独立限时30秒，随后本地校验/接管共享5秒预算。已有账本直接复用；先完整校验、必要时串行接管经理路由、再校验并采集短摘要；随后程序自动检查平台登记，未登记且不在黑名单时幂等自动注册，返回 `registration.state`（`registered` / `removed` / `skipped` / `unavailable`；旧版 Server 可能返回 `pending`）。不再由模型另查清单或另调注册命令。登记有独立5秒预算，不占用前述本地校验预算；失败输出 `stage:registration` 并保留已成功的路由与快照，只修复登记步骤。隔离/显式状态目录传 `--state-dir <目录>`，与后续服务使用同一目录。用户禁止服务/登记或仓库禁止时传 `--no-registration`；只读查询不调用初始化器。正式项目经理记录为 `project-manager.config.json` 的 `manager.threadId`、`manager.registeredAt`；空项目也必须写入并回读确认。已有配置缺失时从既有索引补齐，不重编号。任务级 `manager_thread_id` 仍是回调路由。同一经理不重复写入；保留执行派发身份与状态，仅清除发往旧经理的活动通知去重。路由改变不证明旧执行者已停止或已交接。
3. 校验及路由通过后，查询 `pm-server status --json`。应用缺失时报告 `unavailable` 并继续基础任务管理；自动登记不等于服务已经运行。已有启用授权且未停用时可运行 `pm-server service ensure`，首次启用需用户明确选择。使用第2步返回的登记结果，不重复申请；`registered` 无需用户确认，`removed` 表示黑名单，禁止自动恢复；仅兼容旧版 Server 时，`pending` 按旧版流程处理并说明版本差异。工作台与监测分别报告状态，`STARTING`/`ready:false` 不证明首次检查完成。后续进程故障检测与恢复由程序负责，经理不持续巡检。
4. 初始化阶段只核对已有 PMO 路由；用户本轮仅要求接管时，不派发新任务或启动治理交付。需要 PMO 后按 [PMO](pmo.md) 建立，缺少绑定单独报告，不影响已经验证的经理登记。
5. 初始化结束前运行 `pm-server status --json`（隔离/显式配置场景传相同参数），确认常驻进程仍存活、`/health` HTTP 成功，且返回的服务类型、状态目录、应用目录和 PID 身份匹配；该命令已执行这些核验，仅进程存在或锁文件存在不算正常。若停用，尊重停用意图；已有启用配置内才可按第3步确保并重新核验；健康异常按下节处理，不冒称成功。
6. 简短报告经理接管、工作台、注册、恢复监测启动/复用/停用及 PMO 各自结果，以及本次进程健康结论、边界和**最新可点击看板 URL**，地址取最后一次成功健康检查返回的 `url`，不能仅写“服务已启动”或沿用历史地址。首次默认地址应为 `http://127.0.0.1:9999/`；已有显式配置/旧端口实例仍须报告实际核验地址，不为改默认端口擅停共享进程。未核验成功时明确“当前未确认可用地址”及失败原因，不能把默认地址当成可用。服务/PMO 操作不计入本地校验及登记各自的5秒预算，不能以初始化预算隐藏失败。

完整初始化成功条件：当前经理标题为 `项目经理：<项目名称>` 且已回读确认；`routing.verified:true`，项目级经理与本轮真实身份一致，快照 `registeredManagerThreadIds` 包含该身份，任务验证通过；工作台登记结果另报。只有实际写入并回读的路由算登记，写维护文档或认领角色不算。失败输出具体 `stage` 和已完成结果，不能将部分完成说成全部接管成功。

快照 `routeIssues` 区分 `manager_route_missing`、`execution_route_missing`、`dispatch_identity_missing`。Server 另区分 `execution_observation_missing` 和 `execution_observation_stale`；后两项是观察缺口，不应再次接管、覆盖执行路由或推断空闲。已验证的原生 Codex UUID 与限定引用按既有单宿主兼容规则关联，其他身份不猜。

初始化不启动产品交付、不等待执行回执。后续实际协调活动任务时，向登记执行者发送一次新经理回调路由，回执收到才记确认；经理将重要交接写入相关任务日志，脚本不会自动代写。不可重派仍在执行或用户暂停的任务。

## 已有经理的自然恢复与渐进核对

PM Server可独立查看任务，不以经理会话在线、经理登记、AI宿主登录/信任/观察样本或通知可达作为接入门槛。缺少这些能力时保留独立诊断，不要求用户重复接管。当前缺记录不证明任务停止或完成，也不证明迁移成功。

已有经理发起真正的管理、协调或恢复请求时，先从宿主当前上下文取得可验证的真实会话身份，并确认既有项目管理授权；不能用自称经理、缺缓存或当前正在对话作为授权证据。读取当前项目登记后运行：

```sh
node <Skill>/scripts/activate-manager.mjs --repo <仓库> --manager-thread <当前真实ID> --resume-existing
```

此入口只修复已有标准任务项目，不调用initializer、不创建账本、不注册或恢复已移除来源、不启动服务。项目经理等同当前身份时，仅补齐进行中或待确认的任务的经理路由；配置未登记经理但既有任务路由一致属于当前身份时，可恢复项目级登记。已完成/已取消历史路由保留，原执行/dispatch、任务生命周期和授权不变。原生UUID与对应本实例限定引用只做已知身份等价，不为格式一致无故改写。

程序持原项目锁核对并回读；`REPAIRED`或`ALREADY_ALIGNED`且`verified:true`才算修复已确认。当前登记为不同经理时返回`MANAGER_CHANGED`，缺少可确认归属时返回`OWNERSHIP_UNVERIFIED`，不静默覆盖，也不要求用户为了查看任务重新接管。仅在用户明确变更经理时才使用接管流程。当前真实身份无法核实时不运行写入口，继续可做的只读核对并说明限制。

确认当前身份为既有经理后，按正常初始化第1步核对或修复当前会话标题并回读；缺少能力时保留明确待办，不改变经理身份或重启服务。修复后依当前任务真源、原执行/dispatch与已到达回调核对成果，在原车道持续跟进；仅对已核实事实串行更新并把必要路由修复写任务日志。无变化不重复写日志。不为补缓存重新派发活任务或唤醒旧会话，未确认项保持未知，真实中断/待验收交接按原规则处理。纯status及其他只读请求不触发此入口或路由修改。

## DSH 环境（仅 CLI）

本技能在 DSH 使用 CLI 脚本，不添加工具/命令/预设插件层。历史 `session-<uuid>`、`teammate:`、`subagent:` 路由继续兼容读取；格式可接受不证明用户可见独立会话、命名或恢复能力。需要派发时按当次宿主核验，不能凭标识名称认定符合车道要求。


## 失败与历史兼容

- `prevalidation` 失败时接管未发生；路由或后校验失败也不得宣称完成。保留错误，不重跑整套初始化掩盖首次失败，不继续启动服务。可转只读采集报告可读取状态及校验缺口；校验失败的快照不是可派发证明。
- 历史卡缺日志会被完整校验阻止。依据可核实材料，在已授权范围用简短接续记录引用原卡、注明补记时间和未知部分，再重试；不将全部历史章节逐条搬入日志。不能添加占位记录、绕过校验或声称旧任务已验收。大范围历史迁移须先明确任务范围及归属，不自动批量改真实项目。格式见 [任务系统](task-system.md)。
- 服务失败仅重做有问题的服务步骤，不重新接管路由。连接身份不符、健康超时或存活证据不足时报告，避免盲目重启；地址来自实际核验输出，不能用配置端口冒充可用 URL。已核实服务存在而打开浏览器失败时直接提供 URL。
- 慢诊断单独限时，按具体异常再读环境适配。只有在明确修复需要且已校验的场景才单独使用 `activate-manager.mjs`，正常路径统一使用初始化器。
- 用户/机器配置安装另核授权；配置存在不等于受信任或运行。可选观察缺失为未知或 `WARNING`，不推断空闲、完成或页面验收通过。

## 独立应用边界

初始化不安装或首次启用 PM Server。只读查询使用 `pm-server status --json`。已有启用记录且未停用时可幂等确保，缺少应用或观察则按未知降级；不要求后台存在才能维护任务。状态目录由应用配置决定，不按 AI 宿主目录推算。

已有经理自修复跳过带监测暂停信息的任务，避免路由变化使暂停作用域失效；这些任务保留原路由，待后续明确协调。待办、受阻及已结束任务的历史路由不批量改写。
