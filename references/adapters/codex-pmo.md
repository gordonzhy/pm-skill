# Codex PMO 路由适配

仅在配对或修复本项目 PMO 时读取；职责与正式任务车道边界以 [PMO 协作](../pmo.md) 为准。工具及创建授权以当前环境实际约束为准。


经理初始化只核对已有 PMO 绑定，不因接管而自动创建或派发治理。需要 PMO 且已有相应创建/工作授权时，按当次宿主实际工具和 [Codex 适配](codex.md) 使用用户可见的独立宿主会话；会话内子智能体或仅新上下文不能充当 PMO。真实身份、列表可见性和续行入口未核验时保留绑定并报告未知，不把旧路由伪改为迁移完成。完整职责见 [PMO 协作](../pmo.md)。

1. `node <Skill>/scripts/project-config.mjs --repo <仓库>` 返回白名单字段 `pmoThreadId`。缺失为 null；格式错误、重复定义或引号错误返回 `pmoBindingError` 且 `pmoThreadId=null`，端口/模型字段仍独立核验。出现该错误须保留原绑定并报告 PMO 配对未完成，先修登记，不能按“缺失”新建重复会话或暂停已独立核实的经理工作；不输出无效原值。它是角色路由，不是任务状态。已有 ID 最多读取一次核对归属、未归档及可复用，当前工具不能确认时如实记录未知，保留绑定，不向身份未知的会话发送项目材料，不因缓存缺失新建第二个 PMO。
2. 无有效绑定且有创建授权时，创建/绑定一个可复用、用户可见的独立宿主会话，并回读真实 ID、列表可见性与续行入口，模型按用户选择或项目配置；发现当次命名能力，可用时命名 `PMO：<项目名称>` 并回读；命名不可用或未核验则分别报告，不能用标题代替身份与可见性证据。用户明确要求创建 PMO/按本配对机制新建会话时直接执行。若工具另要求显式“新任务”而当前只有只读查询或普通接管，遵守工具限制并说明 PMO 尚未创建，不用 Skill 代替工具授权、不阻塞经理其他工作。
3. 得到真实会话 ID 后，由经理将 `PROJECT_MANAGER_PMO_THREAD_ID=<真实ID>` 保存到已确认被 Git 忽略的仓库根 `.env`，保留所有原字段，不输出其它配置；若 `.env` 未被忽略先补该本地排除。绑定仅经理写。归档/错误绑定只在明确证据后替换，历史 ID 留相关复盘任务详情，不解档或复用其他项目会话。
4. 首次只向常驻 PMO 发送有界治理检查，不机械创建任务，不将其角色路由登记为产品或复盘任务的执行路由。若检查形成独立交付、需要登记正式复盘任务，则为该任务另建专属执行会话，CSV 的 `execution_thread_id` 登记该专属路由，常驻 PMO 只协调输入与建议。已存在 PMO 的接管只刷新经理回调，不重复全量检查；同一正式任务的补充沿用其专属车道，按 [Codex 回调协议](codex.md) 交接并验收。

创建和路由保存失败分别报告真实状态：创建成功但保存失败时保留实际ID并修复登记，不能再创建。外部工具耗时不冒本地5秒采集预算，初始化仅核既有配对；获授权建立 PMO 后也不等待复盘；首次回复同时报告经理、看板与 PMO 结果。没有任务在执行时 PMO 空闲正常，不安装新的轮询/Hook或后台自动调度。用户仅问状态时不得因此新建 PMO 或派无关复盘。
