# 可选运行观察与恢复监测

实际需要运行监测、出现交接缺失、执行状态不明或监测服务变化时阅读；正常初始化不读取本文。具体观察机制、安装授权、信任步骤、命令、时间窗口和服务地址由当前环境适配提供。

任务索引是项目状态与路由真源。外部运行观察只是可重建的辅助输入；它可以记录活动、等待或结束迹象，但不能决定任务生命周期、依赖、验收，也不能让看板失效。观察器不得写任务详情或状态；恢复监测器最多写仓库后端允许的通知去重元数据。显示通知和恢复检查是独立机制。

执行者优先通过当前适配器已验证的直接回调路径告知经理；经理完成派发和即时协调后结束回合，由回调唤醒收口。恢复监测只是回调缺席时的辅助观察；经理被唤醒后按完整名册核对任务事实。不能把某一种环境的排队消息、会话状态或锁文件当作经理已醒来、执行已失败或任务已完成的证明。真实唤醒能力须由环境适配验证。

监测只检查活动任务及已登记路由。执行者仍活动时不发送恢复；可靠地观察到执行者不活动、且经过必要登记/停止宽限期时，发送有界协调消息，再由经理核对最新回调和成果。经理是否活动只影响送达，不抑制提醒。观察来源、必需字段、关联执行单元或新鲜度缺失时，安全降级为 `WARNING` 并跳过猜测性空闲恢复。缺失或沉默不等于空闲；新执行轮次应有新的通知代次。

对每个受影响任务，可向登记经理发送含具体缺证据及去重代次的警告。相同警告限制重复频率；经理通过调整真实任务状态或带原因和到期时间的监测暂停处理，暂停到期或派发/执行路由/轮次变化后恢复检查。不得为了使界面显示健康而消音未审查警告。消息发送失败保留未确认状态，按环境适配的有限重试规则处理，不转交用户中继。

旧单项目模式中运行看板与恢复观察可由同一本地服务提供；多项目工作台独立提供只读页面，恢复监测由独立用户级服务统一检查已登记项目，旧单项目监测器保留兼容（见 [多项目工作台](workbench.md)）。二者都不能重建任务 HTML 或写入任务事实。页面通过服务事件读取当前任务数据；观察数据只与已登记路由关联，缺失或过期须明确显示为未知或过期。当前环境支持且用户已授权时，经理初始化调用一次适配器的 `ensure` 入口，程序负责首次拉起、复用及后续故障处理；用户明确停用时不得自动恢复。经理不承担后台进程健康巡检、人工重启或持续保活职责，只依据任务事实及时协调状态。程序活着就必须持续完成有期限的检查：局部项目异常隔离并明确报告；全局故障有界恢复，无法恢复则记录原因并失败退出，不能维持假活。启动它不隐含开机自启、系统级持久托管或后台模型调用；顶层进程退出后的恢复能力必须由适配器明确说明，不能声称能自行重启自己。

Codex 的具体安装、信任、时间窗口及兼容服务命令见 [监测适配](adapters/codex-monitoring.md)。

经理主动停止、暂停或撤回执行时，必须在本轮核对成果，同步任务状态、原因、下一步及适用的恢复条件；不得等待后台提醒处理已知变化。执行会话空闲不直接等于任务失败、完成或应该重派，仍按任务系统协调。

## 已登记承诺与运行观察分开

已显式配置本机worker协调入口时，经理以持久交接和责任期限为拉取入口，运行观察仅说明宿主状态。新鲜idle、缺观察和消息拒发都不意味着业务完成或需要重派；即使没有新鲜idle，已到期的未完承诺仍须进入本机核对/有限责任处置。审批拒绝不触发其它通道外发。当前入口仅提供按需reconcile和有界多项目扫描函数，不自动启用常驻服务；PM Server未接入该协议时不能宣称已有后台保证。未安装入口时保持manual覆盖。

责任身份沿稳定commitment/lineage保存，候选修订、manager协调epoch变化、诊断种类和重启不恢复绝对期限、延期次数或升级预算。消费、计划检查和通道处置都不能冒充业务根义务满足。所有执行/经理/扫描宿主都停止时，只保证已持久资料可恢复，不能保证自行唤醒或无限推进。
