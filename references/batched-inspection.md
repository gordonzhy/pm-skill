# 批量检查项目控制面

初始化使用 SKILL.md 的 `--init` 快速视图；它保留任务校验和事实，跳过非必需运行工具，不输出历史证据。派发、恢复、验收等需要更多证据时才使用完整或 `--compact` 视图。

状态、继续、派发、恢复或验收原本需要多次读取时，先使用当前环境适配提供的只读采集方式取得一个有界快照，再为具体缺口深入。快照应覆盖任务计数、活动/待确认/受阻与少量就绪任务、相关详情片段、依赖缺口、登记路由、可用运行观察、仓库差异与工作树、监测提示及任务后端验证。仅采集廉价、本地、只读且可能减少往返的信息。

同一只读批次只采集一次，将完整 JSON 留在工具结果或临时文件，向模型输出紧凑视图；输出截断时读取已有快照中的指定字段，不重跑整套采集。同批任务元数据发生修改后只做必要验证，出现新的状态变化或证据缺口才重新采集。长 README、WORKLOG 和任务详情按章节读取当前摘要、最新派发/授权/阻碍，避免整文件拼接导致截断后再读。

快照是证据，不是授权。运行缓存是观察，进程锁只提示可能在运行，验证通过不等于任务验收，仓库干净不证明成果正确。观察缺失或过期须标明，不用推断填补。

使用快照中的登记路由选择相关执行单元。需要发现当前执行单元时只列举一次，工具支持时批量读取已知相关项；先看简明记录，具体验收失败、矛盾或缺证据才读原始输出。只有路由不在活动列表、或归档会影响同任务车道恢复时，才查询归档记录。

额外检查应回答明确问题：写入范围是否与脏文件重叠，详情与索引是否冲突，观察是否过期，验证失败的具体原因，执行主张能否对应提交/差异/成果/检查，或外部批准是否确实存在。修改与只读采集分开；相关元数据尽量串行合并更新，再运行一次权威验证。不能为了减少调用把验收、对外消息、破坏性清理或专业批准塞进只读采集。
