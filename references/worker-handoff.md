# 执行任务提示与交接

派发工作或验收执行结果前阅读。本文件规定与环境无关的任务内容和证据；终态消息的具体格式、工具与重试次数由当前环境适配提供。

## 派发内容

给独立执行者足够上下文，不复制整个经理会话。派发应指明：任务 ID 与来源标题、稳定执行车道/角色、仓库指令和详情路径、适用的现行规则与优先级、完成标准、允许写入范围、已知并行任务及不重叠约束、必要项目边界、任务日志的最新需求/范围变更、完整阶段成果、连续执行授权、候选固定方式、预期验收与报告位置、自主处理与回报规则（未指定时按下节默认值）、提交/集成归属及已知共享资源使用安排、经理路由与稳定派发 ID、并行批次成员（若有）。执行者仅在范围内完成交付，不能改中央索引、生成看板、任务状态/元数据或任务详情，也不能自行创建、重排、关闭仓库任务；新发现工作在交接中报告。

派发须携带[本技能维护归属](../SKILL.md#本技能维护归属)边界：业务项目的执行者与验收者不得修改本技能源码、共享源、分发模板或已安装副本；经验写所属项目，通用改进交维护建议。只有用户指定的唯一 Skill 维护项目在明确授权范围内派发本技能源码维护；执行者不得自认维护身份。自主排障、经验沉淀及安装/同步授权均不改变源码维护归属。

执行者先核对来源与任务范围，再决定局部可逆实现细节。跨任务/归属、共享契约、持久规则、安全/合规/迁移风险或验收标准缺失时，先查权威来源与安全验证；仍缺规则则只暂停受影响工作，报告最小控制面缺口，继续无关工作。获授权范围内普通读取、编辑、验证与修正无需反复向用户确认。

产品设计任务还应指向仓库现行设计方法及指定工具，说明有证据的工作假设、已确认方向与范围，以及适用的阶段和验收标准。执行者负责发现问题并提出建议；有决策权的人确认目标与方向；经理负责派发、决策路由和证据核验。

## 自主处理与回报规则

遵循[整体推进原则](../SKILL.md#整体推进原则)，减少往返沟通与等待，把执行资源用于解决问题和交付成果。**执行会话对解决问题负责，默认先自主闭环，再合并回报。** 普通报错、测试失败、验收者发现的缺陷、已知环境差异、局部实现选择和范围内的可逆Git操作，先在原车道查明原因、查权威资料、选择有证据的替代方案，修正并复验。保留首次失败和尝试结果到允许的证据位置，阶段交接再汇总；不因首次失败、暂时没想清楚或需要换方法就唤醒经理，不等经理逐步批准。

**默认回报粒度是一份可验收交付，而非执行步骤。** 从实现到自测、独立验收、普通缺陷修正及复验连续完成后，合并一次最终交接。中途仅在以下情形联系经理：派发时明确约定的、可独立评审或使用的业务成果已经形成；需要经理协调真实依赖或作决定；已核实的真实阻碍；同一问题首次达到下述回报阈值；经理主动询问。每次消息必须说明新增可检查成果、对交付/依赖的实际影响或具体决策；没有这些新增事实就留在本车道过程记录。

“阶段”不能由执行者按工具或技术动作任意切碎。读完资料、改完一个文件/模块、形成初稿、提交代码、启动/结束一组测试、拿到截图、修复单项缺陷、独立验收会话启动或返回，均不单独回报；仅有进度百分比、消息标题或候选已准备也不构成阶段成果。未约定阶段交接且不需外部协调时，默认合并到最终交接；临近最终交付的阶段消息也一并合并。相同成果不再以“实现完成”“自测通过”“验收通过”连续发送多个回调。必要的用户可见进度说明不等于向经理发送内部回调，不为满足界面更新频率另发内部消息。

### 相邻汇报最小间隔

**同一任务、同一派发发给经理的相邻两次汇报，间隔不得低于10分钟；本次为最终结束交接时豁免，可立即发送。** 统一以该任务/派发上次实际成功发送给经理的汇报时间计时，跨事件、阶段、问题及消息类型共用一个时间基准，不能换标题、阶段或回调类型重置。没有上次汇报时，首次符合回报条件的消息无需等待10分钟；最终交接前不得把普通进展标作最终结束来规避间隔。

不足10分钟时，把新成果、问题、决策和其他待报事件保留在本车道记录，合并为下一份有界摘要，继续可安全独立推进的工作。最终结束交接立即合并所有尚未报告的事件及其影响。只有实际需要回报且满足间隔时才发送；10分钟是最小间隔，不是定时汇报周期，时间到本身不是汇报理由，不新增 sleep、定时服务或反复检查。

前述约定业务成果、必要协调/决策、真实阻碍、同问题首次达到1小时阈值及经理主动询问，均仍须遵守相邻10分钟间隔，不额外豁免。1小时判定问题是否需要升级，10分钟限制实际消息频率，两者同时适用。等待发送期间，需新增授权或触及受保护边界的动作先暂停，只继续权限内安全工作；不能为了等合并汇报越权操作。可在允许的过程记录中保存成功发送的实际时间与待报摘要，不要求修改中央任务文件或新增运行服务。

每次尝试应验证具体假设或获得新证据；同因无新线索时改变方法或停止无收益重复，不反复运行同一失败命令，也不通过换会话清空问题历史。“必须自行尝试”不要求穷举所有可能或用满时限。

| 情况 | 执行会话如何处理 |
| --- | --- |
| 有安全可行的范围内修复/验证路径，尚未达到约定阈值 | 自主继续，普通步骤不回报经理；解决后并入阶段/最终交接。 |
| 同一问题反复处理超过默认 **1小时** 仍未解决 | 合并回报一次进展与风险，说明已尝试什么及下一步；仍有安全可行路径则继续原车道，不等待回复、不自动结束执行。 |
| 已有证据表明权限内的合理替代不可行，缺少执行者无法取得的必要输入/能力，或必须改变范围/归属/验收标准 | 完成必要的事实核实与安全替代检查后进入升级汇总，无须耗满1小时；发送仍遵守上述10分钟间隔；只暂停受影响部分，继续可独立推进的工作。 |
| 需要新增授权、外部批准/费用，或继续会触及生产数据、安全、不可逆高影响边界 | 在触及边界前暂停受影响动作并准备具体决策汇报，发送仍遵守上述10分钟间隔，不先做受保护动作，也不以“自主解决”绕过限制。 |

1小时是**普通问题的默认回报阈值，不是任务完成时限、强制停工点或每小时例会**。从同一问题首次阻断时的真实时刻计算经过时间，扣除已明确记录的暂停；更换方法、参数或续接上下文不重新计时。派发或项目已有更具体的时间/投入边界时优先遵守，较短的诊断预算不能被默认1小时延长；不要为执行该规则新增定时服务、重复检查或付费调用。

问题回报用一份有界摘要：任务/派发身份、问题及实际影响、首次发生时间与已耗时间、已尝试的不同路径及结果/证据入口、当前能否继续、下一步与推荐项、确需经理决定的最小问题。阈值触发但不需决定时明确“无需决策，继续自行处理”；确实无法推进时写清解除条件。相同问题回报后，只在影响/证据/方案实质变化、需要决策、形成阶段成果或用户主动询问时更新，不定时重复“仍在尝试”。

经理收到进展回报后不自动改为`受阻`/`待确认`、另开车道或接管排障；执行者仍在修正、验证时保持`进行中`。只有核实确实无法推进或正在等待具体外部决策时才按任务系统调整状态。普通问题仍由原执行会话闭环，经理仅处理超出其权限/能力的决定与协调，避免将往返沟通变成新的执行依赖。

## 连续交付与独立验收

主执行会话对本任务的实现、自测、普通缺陷修正、独立验收安排及成果交接负责。检查点必须是可检查的阶段成果，不能把读取、改一个文件、提交、测试或截图拆成等待经理逐步批准的步骤。阶段反馈后，只要后续仍在授权范围内、无真实依赖/阻碍，继续执行；普通工具失败、Git操作及局部选择先按规则自行解决，不绕过权限或受保护动作。

实质交付先固定候选，再由执行会话创建不继承实现历史、用户可见的独立宿主验收会话，核对实际 ID、列表可见性与续行入口；不能用子智能体或仅新上下文替代。仅交付目标、现行验收标准、候选身份、必要环境/访问边界与报告输出位置；不提供实现推理、自测结论或期望它通过的提示。主执行会话保持本任务的协调责任，等待验收会话报告并完成必要闭环，不在验收会话仍检查时结束本阶段、返回完成或要求经理接续。验收者按标准独立执行检查、记录未测/受阻与缺陷，写验收报告，不改中央任务文件、不替作者修复、不批准任务完成。黑盒验收还须遵守 [独立测试](independent-testing.md) 的源码与工具限制。

执行会话读取原始报告后修正普通缺陷，固定新候选并组织受影响范围复验；保留首轮失败和原始报告，不改写验证者结论。复验会话未接触实现过程时可继续使用，否则新建不继承实现历史的独立验收会话。涉及范围、标准、归属争议或穷尽安全替代仍无法继续时才交经理处理，无关工作继续。环境缺少用户可见独立宿主会话能力或创建授权时保留交接，不降级为子智能体或仅新上下文；能力不足仅报告验收缺口，不由经理接手检查或把作者自测冒充独立验收。

## 交接与用户可见回复

已显式接入本机worker协调入口时，执行者先以已登记dispatch和精确信封完成持久publish，再结束回合；可用`pm-worker finish`核正常结束栅栏。直接消息仅作提示，不充当交接存储或经理消费。消息审批拒绝就停止该披露通道，不换摘要、目的地或会话重发；经理从其已授权本机spool拉取，不让用户中转。未安装/未登记该能力时明确manual覆盖，只能保留已知本机报告并由经理主动读取，不能声称自动outbox/唤醒已经启用。入口和保证层见[CLI契约](../docs/cli-contract.zh-CN.md#私有本机执行交接)。

经理恢复、报告当前运行情况或作派发/关闭决定前，先拉取已配置本机交接并刷新必要宿主观察。业务进行中不等于执行会话active；旧活动样本被重新采集也不能续期。缺少可信新鲜样本就说unknown或最后观察状态。消费只证明取到内容；处置必须关联实际业务命令或有限期限/责任主体/证据，不能仅ACK后无限延期。源码存在、通知accepted、进程存活及安装记录均不能证明当前执行或经理已经消费。

执行者在最终回复前先完成仓库写入、独立验收及必要修正/复验，随后在已配置的本机协调入口持久交接，再按当前适配器实际授权且已验证的路径向登记经理发送有界提示；未接入时保留本机交接并明确覆盖缺口。交接仅包含终态、任务与派发身份、提交或候选身份、简短变更范围、验收报告入口及关键结论、确切阻碍/决策，不含秘密、原始日志、硬件标识、长文件清单或内部叙述。传输失败独立于仓库任务结果和用户参与分类；不要求用户复制、转发或重连经理。后续用户决策在执行上下文解决时，由执行者发送有界决策交接，注明是否仍在原范围内。

用户可见最终回复使用日常语言，首行说明“无需行动”、具体行动及完成信号，或带推荐项的决策问题；随后一句话解释结果与实际意义，必要时最多三点说明变化、限制或下一步。末尾可按环境协议添加简短终态/任务/派发回执。通常不超过八行。不以提交号、文件数、测试数或账本状态开头；不附验收矩阵、命令日志、风险表、建议账本动作或内部回调块。省略重要限制会误导时应写明。

需要行动时注明对象、地点或环境、具体步骤、完成信号、不可操作时的备选及必要安全约束。只有方向、范围、架构/归属、外部授权或成本、生产/受监管数据、专业判断或不可逆高影响风险的选择才请用户决策，并先给推荐项；常规实现细节和经理可核实事实不升级。判定受阻前验证权限内合理的安全替代，保留部分成果；已有明确不可行证据时按上节升级，不机械穷举。

## 经理持久记录与验收

经理以交接、登记派发和原始验收报告为起点，检查任务/候选一致、标准覆盖、验证者与上下文隔离、必要证据、未测/受阻及开放问题是否足以作决定；具体缺口才读取所引用证据。经理不重新执行测试、浏览器操作、截图、逐项代码验收或实质集成，报告缺项退回原执行会话补齐，必要专业审批按项目契约另行路由。唯一任务详情中的持久记录应覆盖终态和路由/批次身份、日常语言结果、变更范围、标准与证据映射、检查及结果、重要假设/决策/限制/风险/后续，以及用户行动或决策的完成信号、备选和安全约束。不复制原始日志或整段对话。任务索引仍是唯一状态来源。

行动前核对任务、执行路由及派发身份；同一事件重复送达应去重。完成声明在经理核验期间保持活动；真实需决策转 `待确认`，经理记录决定后、继续执行前恢复活动。并行批次中普通完成项保持活动，全部成员协调与验收后一次性收口。验证失败、未经评审的迁移、未集成工作树或越界编辑均阻止关闭。新工作由经理决定是否立项；需纠正则回到原车道，不在经理会话重复交付。

## 关键事件与任务日志

每份任务卡必须有任务日志。执行者在允许的证据目录保留过程记录、首次失败、修正和复验，普通步骤不逐项回调经理。符合上述回报条件的阶段成果或最终交付时一次性汇总关键事件及依据，经理据此追加任务日志并引用过程/验收报告；问题回报按[自主处理与回报规则](#自主处理与回报规则)合并；必须外部决策的阻碍、需求/范围/授权变化或用户决定及时保留，按上述10分钟间隔合并报告并记中央日志。及时记录不等于每次读取、修改、失败或重试都唤醒经理，详细过程不复制到中央日志。相似的授权追加先由经理更新原任务范围、完成标准、依赖/影响及日志，再通知该任务原车道；独立新任务另建车道。历史失败、变更和旧验收结论保留，纠正以新记录说明，不用最终摘要覆盖过程。


需要提供任务执行过程时，阶段交接同时提交关键活动的实际起止时间（秒及时区）、具体工作内容及依据，由经理写入日志的`started_at`/`ended_at`；未记录的时间明确留缺口，不用检查点间隔推算。日志字段及进行中/更正规则见[结构化任务日志](task-log.md)。

## 知识交接

交接注明本轮值得复用的新知识、适用条件、来源、验证性质和授权内已写位置；先检索避免重复，不擅写经理独占的中央知识。经理按[知识与检索](knowledge.md)归入所属项目真源与已授权私有索引。轻量整理守枚举预算，正式复盘经用户确认后再派发；阶段交付和知识片段不自动授权复盘。

初始化空库的实质多文档盘点同样沿本任务可见车道交付：接收明确来源/私有输出/预算，用`inventory-plan`读取模型提炼范围，提交来源条目并实际check/search，保留部分完成/重试证据，不将盘点冒正式复盘。已有知识先重建，不重复初始化；细则见[知识与检索](knowledge.md#经理初始化首批知识盘点)。
