# 每任务独立执行车道

派发或改变执行单元数量前阅读。环境适配负责把车道、消息、等待、读取映射到实际工具；本文件约束任务与执行拓扑。

- 仓库任务是范围、依赖、状态、证据和验收的持久单位。每个任务 ID 使用专属、用户可见的独立宿主会话，不把前一任务的车道分配给另一任务，即使同领域、串行、小改动或车道空闲。
- 同一任务追加相似需求、修正、复验或恢复时，继续使用其未归档的原车道。新建任务要新建独立车道；不要为了少建车道而混入独立目标，也不要为了每轮消息、参数或小反馈新建任务。任务粒度与变更规则见 [任务系统规则](task-system.md)。
- 默认一个任务一条主执行车道，车道归属于单个任务；同一任务仅在详情明确互不重叠子范围、专属子车道和唯一整体验收负责人时才可并行多个车道。任务详情列明主/子车道实际身份，中央文件仍由单一经理写入。
- 正式实现、独立验收及 PMO 工作均在用户可见的独立宿主会话进行。会话内子智能体、团队子代理及仅新上下文不能替代；创建工具的名字或返回 ID 本身不证明可见性，须通过宿主列表/读取核对真实身份、可见性及续行入口。
- 主执行会话创建只属于本任务、且不继承实现历史的独立验收会话，负责协调、汇总和修正闭环；不另立仓库任务。验收者只读取必要输入，报告记录实际会话身份、可见性核验及隔离方式；CSV仍登记主执行路由，验收路由留在报告。
- 已归档车道不解档复用。原车道不可用时为同一任务建立专属替代车道，在任务日志记录原因、原/新路由、检查点、遗留事项和授权边界，核对现场后续行。替代不取消原任务授权，也不允许沿用其他任务车道。

独立车道不等于所有任务立即并行。按依赖、就绪程度和真实资源控制在制工作，未执行任务保持待办。资料、工具链、可复现检查点可以共享引用；执行会话不能跨任务复用。工作树隔离遵守项目写入和并行策略，不强制每个低风险串行任务单独复制环境。

派发前核对该车道历史归属，不能只看它是否空闲。既有历史共享记录保持真实，不伪造或批量改写历史路由；后续派发按新规则隔离，相关调整写任务日志。经理、PMO与工作台常驻协调角色不是产品任务的执行车道，不借角色会话绕过已立项交付的隔离要求。

用户授权目标或就绪集合后，可在授权范围内创建专属车道、恢复同任务车道并持续修正，无需逐步确认。实质范围变化及受保护行动仍按授权边界处理；工具不支持用户可见独立会话或创建授权不足时，保留交接与未完成项并说明缺口，不自动降级为子智能体、仅新上下文或经理代做。控制面可继续，不假称已派发或独立验收完成。历史子代理路由只作真实历史保留，不伪改为已迁移；不可借恢复旧路由继续正式交付，替代会话按前述规则核对和记录，不自动唤醒旧任务。

派发指向权威任务卡及日志，不复制全会话。默认一次完整交付后合并交接；仅派发约定的可独立评审业务成果、真实依赖协调/决策、阻碍或首次问题超时才中途回报，技术步骤不另作阶段。同一任务/派发的跨事件非最终汇报统一至少间隔10分钟，不足时保留合并、继续安全工作，最终结束交接立即汇总；具体计时及边界按执行交接规则。符合条件的交接汇总关键事件并由经理追加日志，普通问题先由原执行车道自主处理，按[执行交接](worker-handoff.md#自主处理与回报规则)的时限和升级条件合并回报；需要外部决策的阻碍或边界变化及时记录并按10分钟间隔合并报告，受保护动作先暂停，普通步骤不回调；接受交接时先核身份、变更、证据和检查，具体缺口才读完整执行历史。回调不具有验收权，传输失败不让用户充当中继。
