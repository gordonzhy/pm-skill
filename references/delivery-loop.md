# 派发、并行汇合与验收

派发或验收仓库任务时阅读；车道选择见 [执行车道](execution-lanes.md)，交接内容见 [执行交接](worker-handoff.md)，具体创建、等待和消息工具见当前环境适配。

## 派发

只派发后端计算为就绪、已获授权、写入范围互不冲突且没有共同外部决策的任务。每个任务使用专属车道；只有同一任务续行才恢复其未归档车道，不分配其他任务的空闲车道。改状态前核对所有依赖已验收、车道可用；等待依赖或车道时保持 `待办`，实质执行或派发前才设 `进行中`。登记真实执行与经理路由、稳定派发 ID，以及适用的批次 ID 和完整成员名册。临时设置句柄不是账本里程碑。按仓库执行环境规则选择隔离工作树或共享检出；共享文件指定单一写入者，高风险或重叠工作明确审查与集成路径。派发消息指向权威详情、规则、完成标准和允许写入范围，不把隐含的持久政策选择交给执行者。

没有明确执行授权时止于建议派发集。授权目标范围内的安全派生工作可持续推进，无需逐次形式性确认；实质边界变化仍需升级。

规划一轮交付或探索任务时按 [小批交付与投入控制](efficient-delivery.md) 明确整体结果、阻断项、投入边界与检查点，复用已有范围和验收说明。把实现、自测、独立会话验收、普通修正及复验作为主执行会话的一次连续交付，默认最终合并一次交接；阶段回报只用于派发约定的独立业务成果或必要协调，不逐个技术步骤通知经理。同一任务/派发跨事件、跨消息类型的非最终汇报至少间隔10分钟，不足时记录合并并继续安全工作，首次无需等待，最终结束交接立即汇总；10分钟不是周期通知，具体按执行交接规则；提交范围、权限与共享资源安排一次讲清，不把经理回复作为普通下一步的依赖。派发同时说明[自主处理与回报规则](worker-handoff.md#自主处理与回报规则)：普通故障由原执行会话先闭环，默认同一问题超过1小时未解决才合并回报进展；需外部决策或已无安全可行路径时提前升级，项目已有更短预算优先。指定实质集成的执行归属；并发按独立工作和实际资源占用配置。技术范围内的可逆调整由执行者处理，不为每个参数或内部步骤新设审批。

派发前在任务日志记录当前需求、范围/完成标准变更及派发身份；阶段交接时合并关键执行事件和报告入口；真正阻碍、范围变化与用户决定先保留事实，执行回报遵守10分钟最小间隔，经理收到后及时追加。验收前核对日志包含本轮变更、重要失败/修正、验证与决定，不能只保留最终成功摘要。相似小改优先变更同一任务，不为每轮反馈机械立项。

## 接收与汇合

终态交接是待核实证据，不自动等于验收或完成。按任务、执行路由和派发 ID 匹配，重复交接去重；后续证据明确取代早期结果时才接纳。派发后确认完整成员名册、稳定路由和已验证的回调/恢复路径；处理完本轮可立即处理的事项便结束管理回合。回调或恢复唤醒后重新核对完整名册和任务事实，不能因单个成员返回就认定批次完成。若当前环境没有可靠唤醒能力，明确记录能力缺口，并采用有界等待或人工跟进，不把任务无声遗留。需要纠正时回到原车道；缺具体证据才读取完整执行历史。

单任务返回完成声明后，在经理核验期间保持 `进行中`；执行已交付而等待经理开始审查，或具体问题已交给用户且确实等待答复时设 `待确认`，在详情说明等待对象及下一步。经理主动停止、暂停或撤回车道时，在本轮核对成果并同步任务状态、原因和下一步，不等待后台提醒；用户指令停工时及时停止相关车道，记录暂停与恢复条件，不发待确认提醒，也不在此前授权下自动恢复。并行批次采用完成屏障：一名成员完成时先保留其证据，其他成员未终结或未验收前不关闭批次、不宣布部分完成、不释放依赖。达到问题处理阈值的进展回报不自动中断执行或改变状态；经理先区分仍可自主推进与确需外部处理，不为普通排障逐步批示。真实阻碍或决策要及时处理；全部成员终态协调且完成项验收后，由指定执行归属串行完成共享集成及受影响范围的独立验收，提交集成候选与验收报告；经理核对报告后串行更新中央状态，再决定通知用户或继续。用户在执行上下文解决决策时，由执行者按适配器回传；经理记录决定，范围仍获授权时继续原任务与车道，不要求用户转达。

失败、取消、无效交接、范围碰撞或真实阻碍是需要及时处理的事件。观察数据、排队消息和执行者自述都不能单独证明任务应关闭。用户问状态时呈现真实视图，包括批次屏障中等待决策的成员。

完成屏障约束批次关闭和依赖释放，不阻止在已授权隔离范围内交阶段可看结果。阶段结果须注明未交与未验，不冒整个批次完成。资源已释放时，可推进不依赖未验成果的就绪工作，无须等待原车道纯文档收尾；新增阶段或依赖调整仍由经理登记，不能让执行者自行跳过原依赖。

## 验收与继续

经理只核对流程和原始验收报告：任务/派发/候选身份、完成标准覆盖、隔离验收者、实际环境与检查结果、必要证据、集成结论及开放风险是否满足项目门槛。具体检查、自测、独立验收和复验由主执行会话及独立验收会话完成；经理不跑测试、操作浏览器、复做截图或承担实质集成。报告不完整或结果有矛盾时退回执行会话，要求补充/复验，不亲自填补。安全、迁移、合规、共享契约或复杂集成仍保留项目要求的专业独立性和外部审批，普通验收者不能代替。低风险可逆元数据修改按实际风险检查，不为形式创建独立验收会话。执行者最终回复保持简短，详细结果、证据、风险与派发身份由经理写入唯一任务详情。验收后标 `已完成` 并验证；需纠正保持活动并恢复车道；确实不能继续才记录阻碍并设 `受阻`。

关闭任务后重算就绪集合与授权范围：明确可继续的任务立即派发，每个独立任务使用自己的车道，按实际资源决定并发。只有缺授权、真决策、真实阻碍或下一选择实质改变方向、范围、归属、成本、风险时才暂停。单个车道受阻不暂停无关工作。执行者误改中央文件时暂停并行收口、串行协调；派发后范围重叠则暂停一方并确定唯一集成负责人。任务真源不一致先修复或升级，再启动更多交付。

验证按实际变化及风险安排，复用输入与相关实现未变、来源清楚的已有证据；漂移时重验受影响部分。探索的数值安全或构建通过不等于有产品收益；无收益时按事前退出条件处理，不默认追加相似试验。低收益探索停止不等于真实缺陷关闭。

## 里程碑后的 PMO 复盘

较大任务或实质阶段交付验收后，经理主动按 [PMO 协作](pmo.md) 派发有界复盘；跨任务形成一个版本时合并一次。真实完成信号和开放项写清，不以回调终态冒验收。复盘与后续已授权交付并行，不把它默认插为产品依赖；只有发现具体阻断再登记。经理核实并处理建议，让经验进入最小规则/组织改进及后续验证，而不是只归档总结。
