# 日常知识、轻量整理与检索

有用问答、用户纠正、明确决定、可复用方法或新失败边界出现时读取本页。知识在所属项目的已授权私有目录保存；公开产品的内部知识放私有管理区。先查已有记录再新增，简单条目一小段即可，不等正式复盘；无新事实不重复记。经理维护中央知识；执行者只写交接指定位置，由经理归入真源。不要跨越任务写入归属。

## 三种动作

- **日常记录：** 在既有私有记录授权内主动完成，保留来源、适用条件和不确定性。不把模型回答标为工程验证。用户决定引用现有决定真源，不复制成第二份规范。
- **轻量整理：** 可主动处理一个主题的枚举小批内容；先明确预算，运行 `plan-check`，只处理返回的批次范围，到限留下未完项。首版硬上限10条、64 KiB读取、5秒脚本读取预算。模型的思考/编辑时间另设会话投入上限，工具不计量或强制限制模型。跨项目迁移、大量历史重整、重新调查证据、冲突决定取舍先建议，不能以轻量整理名义扩大。
- **正式复盘：** 经理先简短建议范围、理由、问题、预期产出和投入上限，用户确认后才建/派正式复盘任务；同范围已有明确要求不重复确认。使用可见独立宿主会话。里程碑不是自动授权，不阻塞已合格交付。重要正反做法按证据写，原因未确认就保留待验证；改进仍用原任务系统。

“主动”发生在有会话触发的工作过程中，不承诺后台周期运行。会话结束前将值得复用的新知识及时归入真源并更新已授权索引，不把完整聊天当知识。

## 配置与数据边界

`python3 <Skill>/scripts/knowledge.py --help`、`schema` 给出真实能力。Python 3标准库实现，不依赖 `rg`，没有缺少外部工具而少搜的降级。POSIX `flock` 用于写入，`setitimer` 用于正则期限；不支持时明确拒绝对应能力。

复制 [空授权配置](../assets/knowledge-config.example.json) 到用户已授权的**私有**位置，明确填写稳定项目键、知识根、枚举Markdown来源、可写性及授权记录引用/范围；配置和索引都不是公开模板或分享材料。根路径相对配置文件解析，也接受显式绝对路径，不展开HOME、不递归找文件、不扫描仓库/磁盘或真实项目登记表。可将现有任意知识目录映射为根，只补固定元数据块和稳定锚点，不迁移或复制既有正文。全局位置与首批项目必须另有实际授权，空模板不会自动纳入任何项目。

空模板默认不授权任何来源。实际获得该范围授权后，可按下面的**虚构**结构添加项目；替换授权引用，不能把示例当真实授权。`root` 和 `index_root` 均相对配置所在目录；来源必须已存在，或由 `record` 在明确枚举后创建。

```json
{
  "version": 1,
  "index_root": "private-index",
  "projects": {
    "demo": {
      "root": "demo-knowledge",
      "files": ["notes.md"],
      "authorization": {
        "reference": "fictional-user-request-reference",
        "scope": "fictional local private knowledge only"
      },
      "writable": true
    }
  }
}
```

每项目最多100个文件、1000条、4 MiB，每文件256 KiB；所有来源必须在登记根下，拒绝 `..`、绝对来源名及路径任意部分的符号链接；来源必须是普通文件，FIFO/设备等特殊文件立即拒绝。索引根不能与知识根嵌套。所有本工具写入者共享按项目的非等待锁；忙时重试，不删除锁文件夺锁。原子替换保持旧快照，写前二次读取和配置字节比对拒绝变化；读取时再次核对正文指纹与整份派生元数据，损坏/伪造缓存不能扩读文件。外部直接编辑不受锁约束，若与最后提交瞬间竞态，下一次检索/check会拒绝陈旧缓存；没有跨正文/索引的多文件事务。

每次调用只遍历**当前配置**的项目，不读取撤权分区；输出前重新核配置，调用中撤权返回错误。旧分区留作私有恢复材料，不自动删除，不能绕过当前授权拿旧缓存冒真源。配置引用只帮助追溯，不能证明真实用户已授权；操作系统权限和调用者核对原始指令仍必需。CLI不能阻止模型或其他程序绕过它直接写文件，也不能证明来源真实、语义正确或确认引用确实来自用户。

默认输出只含计数与固定错误码。搜索必须显式 `--private-output`，才返回本次授权范围内的私有条目，禁止复制成通用提示词、公开示例或外发。错误不回显绝对目录、配置、正文或系统异常；授权的私有搜索输出仍含真实内容，不是脱敏导出功能。

## 元数据与记录

一份Markdown可以有多个固定块。块前用稳定锚点 `<a id="knowledge-DEMO-K-001"></a>`，块内严格JSON；脚本不猜自由正文。字段约束见 `schema` 和 [条目JSON Schema](../assets/knowledge-entry.schema.json)，[空条目模板](../assets/knowledge-entry.template.json) 需填完整才能记录。

`id/title/kind/summary/scope/keywords/aliases/sources/status/recorded_at/verified_at/basis/replaces/related` 均显式存在；列表允许空但来源至少一项。记录日期与核验日期分开；日期为不晚于今天的ISO日期。`basis=user-decision`不等于工程验证，`engineering-evidence`必须有核验日期，`unverified`不能标为现行。决定类型必须有用户决定依据。脚本只检查声明结构，模型须核原文。来源引用可以是既有决定锚点/私有证据索引，脚本不打开这些引用，因此可访问性与真实性仍须模型有界核对。自由正文、完整证据不进入索引；将需要召回的症状/问法提炼到摘要、关键词和别名。

```sh
python3 <Skill>/scripts/knowledge.py --config <私有配置> record --project demo --file new-note.md --entry <条目JSON> --body <可选正文文件>
python3 <Skill>/scripts/knowledge.py --config <私有配置> build --project demo
python3 <Skill>/scripts/knowledge.py --config <私有配置> check
```

`record`只创建配置已枚举、`writable=true`、尚不存在的文件，拒绝覆盖；现有真源按项目写入约定编辑后 `build`。正文已写但索引失败时返回非零、`source_written=true/indexed=false/recovery=build`；保留正文修正，不谎报整个流程成功。配置先枚举新文件再记录，其他缺失来源会使索引失败并明确报告。

`build`只重建指定项目或全部当前授权项目的分区，不改正文，不覆盖其他分区。项目视图用 `--project`；全局视图用同一私有配置的多个项目分区，不另建正文副本。分区含格式版本、来源SHA-256和条目导航，无完整正文；不含生成时间，因此相同源生成字节相同。生成指纹不是知识有效性证明。

`check`检查字段、稳定锚点、重复ID、关联目标、替代目标状态、替代环、缓存指纹/内容一致性与缺失来源。`replaces`指旧ID，同项目目标必须是 `superseded`；被替代条目必须有后继指向它，旧ID和来源保留。跨项目关联用来源引用，不伪造可校验的本项目关系。一个项目坏不阻断其他分区，整体返回非零/不完整；失败分区保留旧快照但不参与搜索。

## 两阶段检索

先把问题拆成少量词组、别名和范围，搜索引；阅读有限候选的实际正文及来源，再判断适用性。没有命中只说明当前词和范围未命中，可换问法/缩小范围，不推断无知识。不预载全库。检索只读，不自动改决定或合并语义；冲突同时保留来源，不按较新日期擅自择真。

```sh
python3 <Skill>/scripts/knowledge.py --config <私有配置> --private-output search '登录失败' '凭据过期' --project demo --scope 'client v1'
python3 <Skill>/scripts/knowledge.py --config <私有配置> --private-output search 'HTTP\s*401' --regex --limit 5
```

默认字面OR、Unicode `casefold`，无中文分词；`--all`要求所有词命中任一索引字段，`--regex`才启用正则。按 `--project/--scope/--kind/--status`过滤，scope是字面包含、大小写不敏感。排序依次为现行用户决定、现行状态、命中词数递减、项目键和ID；返回记录/核验日期、命中词、命中字段及分数，不冒语义相关度或因果概率。结果显示状态、依据、替代/关联和正文文件/锚点；被替代条目不能直接作为现行规则，现行决定醒目标识仍须读原文。

最多10个256字符查询，结果默认5、上限20，摘要默认200、上限400字符；截断返回 `truncated=true/complete=false`，并用 `results_truncated/snippets_truncated` 区分结果数量与片段截断，每项另有 `snippet_truncated`。正则在主线程POSIX计时器内运行，默认2秒、最多5秒，只覆盖匹配阶段；源读取受文件数/字节数硬界限约束。非法正则、超时、未授权、损坏/陈旧/丢失分区均返回错误/不完整，不能当零命中。搜索校验所有授权来源而非只信索引；数据较多时先指定项目。

## 整理计划检查

`plan-check --plan <私有JSON>`只对枚举来源执行预算内读取并返回批次；不自动合并、不改正文、不启动模型/复盘、不创造授权。计划字段：

```json
{
  "mode": "organize",
  "items": [{"project": "demo", "file": "notes.md"}],
  "budget": {"entries": 5, "bytes": 16384, "seconds": 3},
  "confirmation": null
}
```

按不预读下一条的无缓冲字节流读取，元数据结束标记计一条，无块文件读到末尾计一个待整理来源。到限返回 `limit_reached=true/complete=false`、`limit_reason` 和实际读取量；私有输出含 `start_byte/end_byte` 范围与 `continuation`。计划item可携带非负 `offset` 续读；只处理已读范围，不能据文件名继续读整份。条数到限后即停止，未探测后续正文时保守报告不完整。秒数由覆盖来源open/read的计时器执行，超时保留已完成范围和实际读取计数，不自动继续。计划不能扩大配置授权。正式复盘用 `mode=retrospective`，必须有 `confirmation={reference,scope,confirmed_at}` 的非空记录引用、范围和ISO日期。布尔“已批准”不通过；即使结构通过也返回 `authorization_proven=false`，经理仍须核用户原始确认与实际范围相符。较大投入不能通过多次小批调用绕过确认。

模型读取计划通过不等于模型已守时或只读该批次；独立场景验证和真实私有试点分别报告。正式复盘完成时知识归真源、授权索引可检索、改进有原任务去向和验证信号，不冒改进已见效。

## 经理初始化：首批知识盘点

初始化或恢复时先运行 `inventory-state --project <项目键>`，不是因缺索引就重新提炼。无 `--config` 或配置文件不存在返回 `unconfigured`；项目未授权/不可写返回 `unauthorized`；损坏、无权读取、丢失、特殊文件和不一致收据返回失败，不能当空库。`ready`不重复盘点；`rebuild-needed`或`partial`先build/check；已有未结构化正文为`unstructured`，先适配元数据，不覆盖旧决定。`empty`仅表示配置所枚举知识来源已确认没有条目/正文，且源文档路径可访问；不证明项目所有历史都没有知识。

在用户当前项目初始化的既有读写权限内，普通小范围盘点可连续进行，不逐项询问。只枚举已经明确的少量项目入口/规则/操作说明，不递归发现目录、不扫描HOME、全Git/聊天或其他项目。未知目录先按当前授权有界定位；不能为目录发现扩大读取。没有私有输出位置/来源权限时报告具体缺口，不自动为真实项目创造授权。公开产品内部知识必须进入已授权的私有管理区。一次盘点不是正式复盘，也不启动产品交付。

配置中给目标项目添加可选`inventory`；它与知识正文的`root/files`分开：

```json
{
  "root": "demo-project-docs",
  "files": ["README.md", "rules.md"],
  "authorization": {
    "reference": "fictional-project-initialization-read-scope",
    "scope": "fictional selected project documents only"
  },
  "output": "initial.md"
}
```

此对象是`projects.demo.inventory`的虚构示意，不是授权。来源根相对私有配置，文件明确枚举、最多5份；输出必须已列在该项目知识`files`中且可写，不能与盘点文档或索引混用。初始输出可以尚不存在或仅含空白，提交保留原空白前缀；其他知识来源必须可读存在。状态/计划先核实际目标或最近现有父目录的写入/遍历权限，配置中的可写声明不替代文件系统权限；失败时不读取盘点正文或创建计划收据。权限预检不保证后续磁盘容量/权限竞态，实际完成仍以正文和索引回读为准。空模板仍不默认登记任何来源。

```sh
python3 <Skill>/scripts/knowledge.py --config <私有配置> inventory-state --project demo
python3 <Skill>/scripts/knowledge.py --config <私有配置> --private-output inventory-plan --project demo --max-files 3 --bytes 16384 --seconds 3
python3 <Skill>/scripts/knowledge.py --config <私有配置> inventory-commit --project demo --plan-id <准确计划ID> --entries <提炼条目JSON数组>
```

计划默认3份/16KiB/3秒，硬上限5份/64KiB/5秒；源文件仍最多256KiB。只返回预算内前缀、原始字节数/哈希及`inventory:<文件>#bytes=0-<长度>@<哈希>`来源引用。部分前缀明确截断；模型只从实际读到的内容提炼，来源必须使用该计划准确引用。最多5条新元数据记录，模型选择价值、适用条件和验证性质，不能伪造工程验证/用户决定。预算到限可用已读范围形成首批小条目，`inventory_coverage_complete=false`保留未覆盖范围；库可用不等于整项目已完整盘点，不自动续批扩大投入。

计划/提交同用分区锁，私有收据仅存范围、指纹、预算及完成提示，不缓存原文。提交重新核当前授权、已读来源前缀/文件状态、原空库指纹、条目字段和关系，创建源正文后建索引并回读检查。来源变化/撤权/新知识出现或旧收据损坏立即拒绝，不覆盖。重试同计划同条目保持正文幂等；部分写入保留原文并返回`source_written=true`，先build/check或重试原commit。状态以实际正文/索引为准，不因收据自报完成就信任；成功后正文丢失是失败。陈旧/损坏计划须先核归属、保留原收据，再在明确空库及范围内重新计划，不静默删证或改成空库。

`inventory-state`只读探测。小范围控制面知识记录由经理在既有归属内处理；实质多文档提炼/交付交可见专属执行车道并独立验收，经理不借初始化亲手做大交付，不用子智能体。盘点与经理快速初始化分别报告，可先返回已核接管结果，不把盘点混入已有5秒控制面预算，也不让盘点失败抹掉已成功路由。配置/确认引用仍不证明真实授权，工具不能阻止绕过CLI直接写入，模型总投入另守会话预算。真实项目效果需另有实例范围验证，合成流程不代表已初始化任何真实知识库。
