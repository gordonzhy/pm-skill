# PM Server 工作台配合

统一工作台由独立应用 PM Server 提供，Skill 不再内置或直接启动服务脚本。项目内 `TASKS.html` 是另一套静态前端，仍由本技能生成。

## 使用边界

任务索引、详情和日志属于各项目；应用只读聚合，不代替经理的状态决定或验收。只查询状态时运行 `pm-server status --json`；应用缺失时报告工作台不可用，继续基础任务管理，不自动安装。

明确需要接管经理时，在用户已有启用配置内使用工作台。首次启用应用是独立选择；用户停用后不重新拉起。状态输出区分工作台端点、监测进程、项目覆盖和检查结果，不能只凭 PID、加载标记或旧地址说健康。

## 命令

```sh
pm-server status --json
pm-server service start
pm-server project request --repo <仓库>
pm-server project list
```

`start` 是显式启用；`ensure` 仅在已有启用记录时幂等确保。`initialize-manager.mjs` 通过公共 `project request` 自动登记有效项目，缺少应用时正常降级；黑名单项目返回 `removed`，不得自动恢复。应用路径可通过 `PM_SERVER_BIN` 指定。

项目无需逐个确认，按 CSV 真实路径幂等自动登记，不扫描磁盘。主动添加、移除、恢复和取消屏蔽在工作台设置中操作。移除即加入持久黑名单，不删除项目文件和会话，重启及重复请求都不得自动恢复。显式恢复立即连接并保留 ID；取消屏蔽允许下次自动加入。旧版待确认连接在工作台启动时经校验升级，无效来源显示错误并可重试。历史或格式错误的项目显示错误，不当作零任务。

默认端口 9999，报告最近成功端点核验的实际 URL。隔离测试指定独立 `--state-dir` 和端口，不争用正式实例。应用自己的 README 定义安装与运行目录，不能沿用 Skill 目录推算。

## 版本与兼容

跨项目公开约定见 `../contracts/protocol.json`。应用版本、CLI 契约和项目格式不兼容时，停止对应自动化并说明原因，基础项目管理仍可继续。历史 `project-manager` 的服务、登记与运行数据不会随 Skill 安装自动迁移。

## 宿主配置与延迟运行验证

Server全局仅检查自身及项目来源；按实际选用宿主分别检查接入配置，不能因CLI存在自动认定用户使用该宿主。Codex必要配置是Hook回传入口（定义、命令、状态绑定）及Server发送通道；配置完整即可报告“已配置，待运行验证”，不要求登录检测、首个事件或真实投递回执。实际Hook触发、通知收发/回传和经理执行对齐在后续真实请求/事件核验；后端接受不证明两端收到或已处理，也不证明同一消息关联回执。其他宿主只报告已实现能力，不套用Codex命令。检查范围选择不安装、卸载或启停宿主能力。

缺配置可提醒，不阻止工作台查看任务；已有经理的管理请求自修复与纯状态只读边界保持。未经授权不为验收发送真实通知、猜经理身份、唤醒或重派执行会话。
