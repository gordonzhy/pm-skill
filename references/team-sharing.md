# 团队内部分享与验证

本说明用于团队内部传递项目经理 Skill。它不构成公开市场的插件清单、发布者身份或平台审核材料。团队在分发时应指定维护者和问题反馈渠道，不在包内预填个人姓名、邮箱或内部地址。

## 支持范围

- 当前可运行实现使用 Codex 适配、仓库中的 `TASKS.csv` 与任务 Markdown 详情、Node.js、Python 3、支持 POSIX `flock` 的系统和本机浏览器。其他执行环境或任务后端须另配适配器；不能把现有脚本直接当作跨环境实现。
- 分发的是 Skill 文件夹。接收者先阅读仓库规则；安装和自动启动看板不等于获得产品交付或部署授权。
- 每个仓库可用被 Git 忽略的根 `.env` 设置兼容旧项目服务端口、模型取值及 PMO 绑定；共享工作台端口由独立服务配置。分享仓库或 Skill 时不附真实 `.env`；接收者按本机情况配置，未配置时使用默认值。
- 团队维护者负责处理安装失败、Hook 信任、任务索引兼容性和看板服务问题。反馈时提供复现步骤及必要的脱敏错误摘要，不附完整任务详情、会话缓存或密钥。

## 干净环境验证

在待分享的 Skill 文件夹内运行：

```bash
python3 scripts/verify_team_share.py
```

脚本把同一份 Skill 安装到临时 `CODEX_HOME`，从安装后的副本执行 Node 和 Python 测试，完成后删除临时目录。它不会安装用户级 Hook、改动真实仓库或启动正式项目服务。测试需要本机允许绑定和访问 `127.0.0.1`；沙箱禁止回环访问时，应在团队允许的测试环境重跑，不能把权限失败记作功能通过。

## 安装与全局替换

普通 Codex 安装优先使用内置 `$skill-installer`，指定本 Skill 的 GitHub 仓库根目录与安装名 `project-manager`；本地副本可按标准发现目录放置。具体步骤与已有安装处理见[安装指南](../docs/getting-started.zh-CN.md#安装)。下面的候选安装器用于需要备份、哈希比对和回滚的本地更新，不是使用本技能的必要条件。

验证通过不自动授权全局替换。获明确安装授权后可运行 `python3 scripts/install_local.py --codex-root <目标Codex目录>`；缺省目标为用户全局 Codex 目录，测试只能显式指向临时目录。安装器先取得目标级 POSIX 内核锁，暂存完整包、校验后用精确目录重命名切换，已有安装保留备份；最终安装逐文件哈希必须与暂存候选一致，失败恢复原目录并保留失败工件。并发同目标安装明确拒绝，不合并或嵌套目录。候选测试使用隔离状态，不连接正式服务。

## 可复现的使用场景

| 类型 | 用户请求或情境 | 期望行为 | 验证方式 |
| --- | --- | --- | --- |
| 正例 1 | “看一下这个项目现在有哪些事在做、哪些事可开始。” | 只读任务真源，区分活动、就绪、待确认和受阻；不把运行观察当成完成证据。 | 使用含四类状态的示例仓库检查摘要。 |
| 正例 2 | “按依赖安排下一批已经授权的任务。” | 只派发依赖已完成、无真实阻碍且写入范围不冲突的任务，并登记稳定路由。 | 在隔离仓库核对任务状态、路由和未就绪任务不变。 |
| 正例 3 | “打开这个项目的看板。” | 任意项目复用同一本机用户工作台；有效来源自动登记，黑名单阻止自动重加，加入不接管经理。 | PM Server 的 `workbench.test.mjs` 的服务去重、登记、隔离和资源路径测试；实际交互另做浏览器回归。 |
| 正例 4 | “执行会话正在运行，经理暂时空闲。” | Hook 观察只辅助显示；恢复监测不发送重复或错误唤醒。 | PM Server 的 `session-runtime-hook.test.mjs` 与 `project-manager-recovery.test.mjs`。 |
| 正例 5 | “执行者说任务做完了，请验收。” | 主执行会话组织隔离子智能体独立验收并修正/复验；经理核对派发/候选、流程与原始报告后决定状态，不重复执行具体检查。 | 使用有交接但缺验收证据的示例任务进行人工行为检查。 |
| 反例 1 | 只问“项目现在怎样”，没有授权新交付。 | 报告现状，不启动新的产品任务。 | 用仅含状态问题的示例对话检查回复与任务索引。 |
| 反例 2 | 依赖未完成、缺路由或 Hook 缓存过期。 | 保持任务未就绪或运行状态未知，不能猜测空闲、失败或完成。 | `test_validate_tasks.py` 与 `project-manager-recovery.test.mjs`。 |
| 反例 3 | 执行者交接“已完成”，但成果未集成或验证失败。 | 不将任务标为已完成；记录缺口并回到原执行车道。 | 用缺失成果和失败检查的示例任务进行人工行为检查。 |

表中自动化测试只证明对应的脚本行为；派发判断、验收和授权边界还须用隔离仓库与实际可用的会话工具检查，不因脚本通过就宣称全部场景已通过。

## 数据与权限说明

- 观察与后台由独立 PM Server 提供，数据目录和平台能力以其当前版本说明为准；安装配置与真实事件投递分别验证，缺少时安全降级。
- 本机工作台绑定 `127.0.0.1`，按登记读取各项目 CSV、详情及已登记会话观察；主动选择文件时可浏览本机目录/CSV名称，需同源凭据，不返回文件内容。页面不提供任务写入接口。页面的筛选偏好与待确认通知去重记录保存在浏览器本地存储。不要把包含真实任务资料的看板地址通过端口转发或公开代理对外开放。
- Hook 缓存、服务日志和浏览器本地数据均由使用者所在环境保存；团队共享包不应包含任何运行缓存、真实项目任务文件、凭据或日志。退出分享时，按团队的本机数据管理流程停用 Hook/看板并清理这些本地数据。

## 维护信息

内部维护责任人、反馈渠道和分发版本由分享此包的团队在其内部发布记录中填写。若将来转为公开发布，另行准备发布者身份、公开支持入口、隐私政策、条款和平台要求的审核材料；本文件不代替这些材料。
