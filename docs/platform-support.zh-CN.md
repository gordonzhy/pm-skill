## 实验增量／待完善

当前源码标记 `0.1.0-rc.8` 包含 **Unreleased** native CLI 增量，下载的旧分发物可能不同；使用前核对所选提交、[变更记录](../CHANGELOG.zh-CN.md)和实际能力输出。这些增量与上方已验证工作流分开：

- **本机工具已实现：**通用本机 CSV 事务、一致快照、受限恢复及显式 worker 发布／拉取 [3][5]。这是一套实现，不是三平台宿主集成；写入支持 macOS 本地 APFS、Node.js 22+、Python 3.10+，采用 OS owner 自证而非已认证 AI 身份。不支持的平台、linked worktree 和 Git index 布局会拒绝。
- **原生能力未提供：**`dispatch continue`、`dispatch message`、强宿主经理换代、跨项目 handoff/inbox、原生工作台集成 [4][7]。这不否定经理主导的接续或现有 Server 工作台可用。
- **仍未验证：**完整已认证原生宿主交付、普通应用内可见／恢复和完全无人值守运行 [4][7]；通用本机测试及合成对端不能证明这些结果。

## 适用范围与引用

1. **安装：**见[安装指南](getting-started.zh-CN.md#安装)和 [Codex](../references/adapters/codex.md)、[Claude Code](../references/adapters/claude-code.md)、[DSH](../references/adapters/dsh.md) 适配。Codex 的现有管理工作流已经实际验证可用；目录存在仍不能替代未经验证宿主或新安装的加载检查，Claude Code 和 DSH 尚需补足该验证。
2. **规划：**[管理规则](../SKILL.md)与[任务系统](../references/task-system.md)提供目标、归属、依赖、任务日志及证据审阅规则。旧 18 列 CSV/HTML 项目沿用既有工具；新 `project-files/1` 项目使用本地 CLI，不能混用写入器，也不能从脚本可用推断模型管理成功。
3. **本地 CLI：**[CLI 契约](cli-contract.zh-CN.md)覆盖初始化、规划修改、保护、一致快照与受限恢复。在 Skill 目录运行 `node scripts/pm-cli.mjs capability inspect`：`local-command`／`local-query` 是本机实现，`host-command` 要求另建可信宿主绑定，`unavailable` 会拒绝执行。schema 或命令名称存在不等于可执行。
4. **执行：**现有 Codex 经理主导派发与接续已实际验证可用；另需区分，[Codex 工具映射](../references/adapters/codex.md#工具映射与能力验证)区分团队子代理与独立 CLI 线程、传信与开启回合、名册与会话全文，其中验证表针对特定 CLI 基线。另外，当前宿主限定检查已确认团队创建、名册及运行中双向传信；不更新该基线结论，也不代表空闲经理唤醒或产品自动派发通过，使用前仍须发现实际宿主工具。实验性的[owner 宿主入口](cli-contract.zh-CN.md#显式-owner-入口)要求显式私有配置及认证，不证明普通应用内可见／恢复。原生 `dispatch continue`、`dispatch message` 和经理换代仍不可用；其他平台不能套用 Codex 工具假设。
5. **交接：**现有工作流通过执行报告、经理拉取和证据审阅完成交接；另行启用的[私有本机执行交接](cli-contract.zh-CN.md#私有本机执行交接)已实现登记、持久发布、经理拉取、消费及有证据的处置。[虚构项目示例](../examples/local-worker-walkthrough.mjs)验证本地文件流程，不启动 AI、通知服务或连续扫描器。执行者须显式发布；包装器不能拦截未受管宿主的终止。旧格式兼容不写中央账本；消费或检查点不会消除未完业务责任。
6. **观察及提醒：**属于可选 [PM Server 集成](getting-started.zh-CN.md#搭配-pm-server)，与原生 CLI 分开。DSH 观察器只记录 Cordis 生命周期事件，不创建工具、不派发代理、不发通知。配置、事件接收、通道接受、实际收到、唤醒和经理处理须分别取证；缺观察是未知，不是空闲或完成。本机 worker 协调器提供显式 reconcile 与有限责任管理，PM Server 不会自动消费该协议；实验性宿主监测须显式构造，不安装后台服务。
7. **验收：**现有 Codex 经理主导的审阅及验收已实际验证可用。[交付规则](../references/delivery-loop.md)与[独立测试](../references/independent-testing.md)指导经理，质量结论仍需证据及判断。[实验性宿主 profile](cli-contract.zh-CN.md#实验性进程内宿主-profile)已实现受控交付／独审／决定／关闭 API，验证使用合成对端，不能证明已认证模型旅程。跨项目 handoff/inbox、原生工作台集成仍不可用；三个平台的完整真实宿主无人值守交付均未验证。

Codex 可直接体验现有经理主导工作流；Claude Code 和 DSH 继续作为适配目标，待实际加载、协作与跟进路径验证后再标可用。仅安装 Skill 不会启用 PM Server 集成。
